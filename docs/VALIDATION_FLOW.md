# 設定・読取・保存を、確認する対象ごとに分ける

## 今回の担当

| 対象 | 変更・判断 |
|---|---|
| csv_options.py | 本文、ヘッダ一項目、項目一覧、自由key-valueの生成入口で静的な設定を確定 |
| csv_headers.py | validate_headerを廃止。説明行、項目の解釈、自由key-value、出力を目的ごとに分離 |
| text_header.py | 一対の行と複数対の行を分け、各処理の流れを短くする |
| block_rows.py | BlockRowへ列・所属先・見出しを集約。メタはCSVの共通設定を利用。入力の形は読書き時に照合 |
| kv.py | 本文の文法とヘッダ生成メソッドを分離。方式とキー一覧の矛盾を作らない |
| jsonl.py | 通常モデル / dictの生成入口を分離。操作内で一度確定した対応表を全行で共有 |
| yaml.py | 静的なfooter_fieldsは設定生成時に確認。文書・アンカー・マージに関する検証は入力処理へ残す |
| two_table_csv.py | 保存前の重複する件数照合を除き、生成文書の再読で件数・文法・編集済みモデルを一度確認 |
| versioning.py | 保存版の既定値の確認を共有し、実際のcast経路・入力版の照合は変換時に残す |
| ModelBinding / Repository / JSON | 接続・外部入力・保存直前でそれぞれ保証する対象が異なるため、必要な確認は維持 |

設定を小さなクラスへ分割するための基盤は追加していません。CSV設定型は4種類です。単一の設定の中で同時指定が禁止される方式は、名前付きの生成入口へ置き換えています。

## 処理の塊

各処理は、準備・境界の確定・値の対応付け・モデル生成・文書全体の照合という段階で読みます。短い条件を一つずつ関数へ追い出すのではなく、同じ目的で読める単位をまとめています。メソッド名、空行、節目のコメントで、次に何を確定するかを示します。

## 残す必要がある確認

- 読んだファイルの列数・件数・引用符・キー重複。設定の正しさでは保証できません。
- Pydanticによるモデル生成。CSVの文字列復元や版変換の完了とは別です。
- JSONの重複キー・非有限数、YAMLの循環参照。解析中のデータ欠落を防ぎます。
- dictのキー・循環参照。呼出側が編集した保存対象は、読み込んだ直後とは限りません。
- JSONL追記前の既存メタと末尾確認。今回の設定を作っただけでは既存ファイルを保証できません。
- 上書き制御・ロック内の存在確認・置換直前の編集権確認。並行状態は時点ごとに変化します。

text_headerやfield_pathsのように値を引数で受け取る共通関数は、直接呼べる入口として必要な引数確認を残しています。同じ固定設定を再点検することとは分けています。

画面、解析アルゴリズム、Excelエンジン、共有編集の規則は今回の変更対象ではありません。大きな新設計や未提示形式の推測も追加していません。

## 最新のVersionedRowsの例

```powershell
python -m examples.versioned_csv outputs/versioned-csv
```

旧版と現在版のCSVヘッダをそれぞれ宣言し、同じVersionConverterとcast関数へ接続します。入力はdictで読み、metaと本文のupcastが終わってから現在モデルを生成します。現在版CSVとJSONL、旧版CSVへのdowncast出力を同じFileReader / FileServiceの呼び方で実行します。

異なる版のヘッダを、ファイル内容から自動で推測するサンプルではありません。アプリが選択した入出力先に合う構成を明示しています。count=1の意味は旧データの値として保ち、本文2行から勝手に更新しません。旧形式の空行境界例versioned_rows.pyも、例外形式の確認用として残しています。


JSONL・KV・BlockRowsの設定整理と移行方法は[各形式の設定](FORMAT_OPTIONS.md)を参照してください。
