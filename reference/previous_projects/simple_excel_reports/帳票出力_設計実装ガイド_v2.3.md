## 1. 目的・設計の結論

`Record`（1レコード＝帳票の1行）が可変長の`list[Item]`を持つ。1つの`Item`には複数のフィールドがあり、**シートごとに選ばれたフィールドだけを出力**する。`Item`が複数あれば、**帳票共通の並べ替え規則**を適用し、各シートで同じ並び順のまま右方向に繰り返す。

出力方式は次の2つを共存させる。

| 方式 | レイアウトとフィールドの対応を指定する場所 | 適用場面 |
|---|---|---|
| **コード定義方式** | Python側の帳票定義 | 表の構造をプログラムで制御したい場合 |
| **Excelテンプレート方式** | `.xlsx`内の定義 | セル結合・罫線・印刷設定・外観をExcel上で整えたい場合 |

**共通化の境界:** 両方式が定義した「どのシートへどのフィールドを出すか」を統一的に読み取った後、**データの抜き出し・Record単位のItem並べ替え・行の形成**を同じ仕組みで行う。書式やExcel座標まで無理に共通化しない。

### 1.2 基本原則

- 業務モデル（`Record`、`Item`）に、セル番地・シート名・罫線などの出力都合を持たせない。
- フィールドの出力先は**帳票定義**に置き、Record・Itemの型定義と切り離す。
- **各シートのRecord一覧列は独立した指定**とする。共通の列構成を強制しない。表示するフィールドの選択と順序はPython定義またはExcelテンプレート側で決める。
- **Recordのシート別振り分け（どの行を出すか）**と、**Itemのシート別フィールド選択（どの列を出すか）**は別の責務とする。振り分け条件は**Itemの単一または複数フィールド値**を対象とし、帳票定義側に置く。条件を評価して対象Recordを先に確定させる。
- **シートごとの条件判定は独立**させる。同じRecordがシートA・シートBの双方の条件を満たせば、両シートへそのRecordを1行ずつ出す。いずれかのシートに出したことを理由に他シートから除外しない。
- **1つのItem内の条件の結合はAND／ORをシートごとに指定可能**とする。ANDでは同じItemが全条件を満たし、ORでは同じItemが少なくとも1条件を満たす。**異なるItemの条件成立を寄せ集めてAND成立とはしない**。初期実装ではANDとORを入れ子で組み合わせない。
- フィールド条件の比較は**一致・不一致・大小比較**（`==`, `!=`, `<`, `<=`, `>`, `>=`）に対応する。例えば「数量が10以上」や「日付が指定日より前」。区間指定は2つの大小比較をANDで組み合わせれば表現できる。集合への所属（IN）や部分文字列一致（contains）は初期対象外。
- **複数Itemの判定はANY方式**とする。各シートに定義された条件全体をItemごとに評価し、**1件でも一致すればRecord全体を出力対象にする**。一致したItemだけを抜き出さず、すべてのItemを**指定フィールドで並べ替えて**横展開する。条件判定は順序に依存しない。
- **Itemのフィールド値が`None`の場合、比較演算子の種類によらず、その比較だけを不成立とする。** AND/ORの評価にはこの不成立をそのまま渡す。`None != 値`で一致扱いにしない。
- 振り分けのために参照するItemフィールドと、出力するItemフィールドは同じでなくてもよい。振り分けに使う条件は「判定NG」等の特定値に固定しない。
- シートごとの上部共通値検証とItem展開数の計算は、**そのシートへ振り分けたRecordだけ**を対象とする。入力全件を一律に検証しない。
- **どのシートの条件にも一致しないRecordは出力しない（質問18）**。未分類シートを自動生成せず、エラーにもせず、そのRecordを帳票から除外する。
- `Record.items`が空の場合、現在の「Itemの値を評価する条件（ANY）」には一致しないため、**どのシートにも出力しない**。質問12の「Itemが0件でも1行を維持する」は、別の手段で出力対象となった場合の**行の表現規則**であり、今回の**振り分け規則**とは区別する。
- 入力Recordが0件でも帳票定義からシートと列見出しを生成する。上部のRecord由来の値は空欄とし、Recordデータ行は作成しない。
- **並べ替え条件は全シートで共通とし、各Recordの`items`内部に適用する。Record一覧の行順は変更しない。** 元のRecord／Itemモデルを破壊的に書き換えず、出力用の並びを作る。同じRecordが複数シートに出る場合、そのItemの並びは両シートで一致する。
- Python方式のItem見出しは、Itemの値から自動生成するのでなく**帳票定義の名称**を用いる。任意個数に対する名前の付け方は未確定。
- **各シートにItemの出力対象が0件でも、Item 1件分の空の見本枠を確保する**。データ用マーカーや仮の値は完成帳票へ残さない。
- 上部値の一致検証は、**そのシートに振り分けられたRecord**が1件以上ある場合に行う。シート内0件では比較不能のため検証せず、上部値を空欄とする（異常とはしない）。
- 同じレコードと同じ帳票定義なら、コード方式・テンプレート方式のどちらでも、**出力するデータの意味と順序**をそろえる。
- テンプレートに既存の装飾がある場合、その装飾の正本は`.xlsx`とする。
- 最初から汎用テンプレートエンジンの全機能を作らず、必要な部分から拡張する。
- Item出力領域の**右側には別の固定項目を配置しない**。既存項目の右移動機能は作らない。
- Record一覧の**下側には別の固定項目を配置しない**。既存項目の下移動機能は作らない。
- 上部のキー・値（**1シートにつき1回だけ表示する情報**）と、Recordごとに繰り返す一覧の列とを、別の役割として扱う。上部の値は**Recordのフィールドから取り出す**。上部に出す各フィールドは、**そのシートの対象Record全件で値が一致することを必須**とし、不一致ならエラーにする。
- コード方式は、上部のキー・値の下に**Item単位の2段見出し**を置き、Itemの上段見出しを横結合する。テンプレート方式の見出し段数・結合はExcel側に委ねる。

## 2. 入力と出力の具体例

### 2.1 入力データのイメージ

以下は**概念例**であり、実際のフィールド名を決めるものではない。

- `Record R001`：条件Aに合致するItem値を持つ。共通フィールド「ID、名前」＋ `items=[Item1, Item2]`
- `Record R002`：条件Bに合致するItem値を持つ。共通フィールド「ID、名前」＋ `items=[Item1]`
- `Record R003`：`items=[]`（Itemなし）。Item条件に一致しないため、**どちらのシートにも出力しない（質問18）**。
- 各Itemに、フィールド `A`、`B`、`C`、`D` がある。**振り分けに使うフィールド**は、必ずしもA～Dの出力フィールドと同じとは限らない。

### 2.2 帳票定義のイメージ

| 出力先 | Recordの振り分け条件 | 一覧に出すRecordフィールド（順序も指定） | Itemから取り出すフィールド | 1 Itemの使用列数 |
|---|---|---|---|---|
| シート1 | Itemの指定フィールド値が条件Aに合うRecord | `ID`、`名前` | `A`、`B`、`C` | 3列 |
| シート2 | Itemの指定フィールド値が条件Bに合うRecord | `ID` のみ | `D` | 1列 |

※ 条件A/Bは説明用のラベル。例えば「Itemの`種別`がA」の単一条件や、「Itemの`種別`がA、かつ`数量`が10以上」の複数フィールド条件などを想定する。**複数フィールドのAND／ORはシートごとに選択でき、同一Itemの内部で判定する。複数Itemの間ではANY（1件でも条件全体に一致したらRecordを出力）とする。** 使用可能な比較演算子は一致・不一致・大小比較とする（質問20）。振り分けとItemの出力フィールド指定は別である。

### 2.3 出力結果のイメージ

**シート1の内容（データの列構成を示す概念表）**

| ID | 名前 | Item1:A | Item1:B | Item1:C | Item2:A | Item2:B | Item2:C |
|---|---|---|---|---|---|---|---|
| R001 | 設備1 | 10 | 20 | 30 | 40 | 50 | 60 |

**シート2の内容（データの列構成を示す概念表）**

| ID | Item1:D | Item2:D |
|---|---|---|
| R002 | 101 |  |

**重要:** この概念表では**シート1にR001、シート2にR002**を振り分ける。振り分け条件はItemのフィールド値を参照するが、**抽出対象はRecord全体**でありItemインスタンスを分割しない。`R003`はItemがなく、条件に一致しないため未出力（質問18）。質問12の「Itemが0件でもRecord行を残す」は**出力対象となった後の行の扱い**を定めたものであり、今回のItem条件による振り分けに優先しない。

### 2.4 Python定義方式の配置例（質問7・11を反映）

上部にRecord由来のキー・値を**3件**出し、**Item条件Aに合致したR001をシート1に出す**場合の配置例。Itemの3フィールド（A・B・C）を2件分展開する。キー名・値は説明用である。

| Excelの行 | A列 | B列 | C列 | D列 | E列 | F列 | G列 | H列 |
|---|---|---|---|---|---|---|---|---|
| 1 | 帳票名 | 点検一覧 | | | | | | |
| 2 | 対象期間 | 10月 | | | | | | |
| 3 | 作成部署 | 担当課 | | | | | | |
| **4（見出し上段）** | **ID** | **名前** | **測定枠A（C4:E4を結合）** | （結合範囲） | （結合範囲） | **測定枠B（F4:H4を結合）** | （結合範囲） | （結合範囲） |
| **5（見出し下段）** | （A4:A5を縦結合） | （B4:B5を縦結合） | **A** | **B** | **C** | **A** | **B** | **C** |
| **6（Record1）** | R001 | 設備1 | 10 | 20 | 30 | 40 | 50 | 60 |

- 上部情報が**N件**のとき、キー・値は`A1:B{N}`、**見出し上段はN+1行目、下段はN+2行目、Record開始はN+3行目**とする。
- Item見出しの**上段**は帳票定義で指定した名称を用い、対応列数分だけ横結合する（上記の「測定枠A／B」は**設定名の例**）。**下段**はシートごとに選択されたItemフィールド名を表示する。見出し名は出力位置ごとに指定し、必要な位置名が不足する場合はエラーとする。
- 一覧で選んだRecord自身のフィールド（例：ID、名前）は左側に指定順で並べ、見出しは原則として**上下2行を縦結合**する（2段見出しの高さをそろえるため）。
- シートごとにRecordフィールドの数・順序、Itemの出力フィールド数は異なってよい。
- 上部キーが**0件**の場合、1行目と2行目が見出し、**3行目からRecord**を出力する。
- Recordが何件あっても上部キー・値はシートごとに1回だけ表示し、そのシートに抽出されたRecord同士で値が一致することを検証する。
- **テンプレート方式はこの2段見出しに固定しない。** Excelに定義された見本見出し（段数・結合・文字・書式）を使用し、Itemの増加に応じて対応する見出し領域も横に繰り返す。
- 両方式ともItemフィールドの選択、**指定フィールドによる並べ替え後のItem順**、Recordの値は共通にし、**見出しの見せ方だけは方式ごとに異なってよい**。
- ItemがないRecordについては、今回のItem値条件では**対象シートがないため出力しない**。将来、条件とは別の手段で出力対象として指定する場合には、質問12に従いRecord列だけを持つ1行として表現する。

### 2.5 入力Recordが0件の場合・シート別に対象0件の場合（質問13・14）

入力が空リスト（`[]`）の場合、**または特定のシートに合致するRecordが0件の場合**も、空帳票を作成する。出力先シートや列見出しは帳票定義から取得できるため、対象Recordの存在を必須にしない。

- **両方式共通:** シートは作成し、各シートで指定したRecordフィールドの列見出しを表示する。Recordデータ行は0行とする。
- **上部キー・値:** 表示キー（項目名）は定義どおり残すが、Recordから取得する値は空欄とする。一致検証は行わない。
- **Python定義方式:** 上部キー・値の直下に2段見出しを作る。Recordが0件でも**1 Item分の空の見出し・列枠を表示**する。上段の名称は帳票定義による。
- **Excelテンプレート方式:** テンプレートの位置・書式・見出しを尊重して空帳票を作る。**1 Item分の見本ブロックを残し**、値のセル・未処理のマーカーは空欄にする。
- 「対象Recordは存在するが全件の`items`が空」という場合と、「対象Recordが0件」という場合は異なる。前者はRecord行を残し、後者はRecord行を作らない。

### 2.6 シート別のRecord振り分け（質問14・15で確定）

入力Recordが100件でも、同じ100件を全シートへ出力するとは限らない。例えばItemの値に設定した条件Aに合う70件をシートA、条件Bに合う30件をシートBへ出す。**同じRecordが両方の条件を満たす場合は両方に出力する**ので、シート別の件数の合計は入力Record件数と一致するとは限らない。

1. 帳票定義から各シートの**Record抽出条件**を取得する。条件は**Itemの1つまたは複数のフィールド値**を参照する。
2. 各シートの条件を**それぞれ独立して、Itemごとに評価**する。**いずれか1件のItemが条件を満たしたらRecord単位で選択（ANY）**。複数シートに一致するRecordはすべての該当シートに含める。
3. そのシートに選ばれたRecordだけを対象に、上部の共通値の一致を検証し、最大Item件数を求める。
4. シート別のRecord一覧列・Itemフィールド指定に従い、1件1行で出力する。**一致したItemのみを抽出せず、全Itemを指定フィールドで並べ替えた順に横展開する。振り分けに使ったItemのフィールドを一覧に出す必要はない。**
5. **どのシートの条件にも一致しないRecordは出力しない**。Itemが0件ならANY条件を満たすItemも存在しないため、同様に出力対象から外れる。
6. 条件に合うRecordが0件でも、そのシートを消さず、**空帳票**として見出しを出す。上部の値は空欄とする。

**複数シート一致の例**：Record R010について、Item1がシートAの条件に一致し、Item2がシートBの条件に一致するなら、両シートへR010を1行ずつ出力する。**どちらのシートにもItem1・Item2を含む全Itemを、帳票定義の並べ替え規則に従って横展開する。**

**条件に関する確定事項**：特定の「判定」フィールドや「NG」値に固定しない。シート別の条件をコード方式ではPython側、テンプレート方式ではExcel側の定義から読み取り、共通の条件表現へ正規化する。条件評価はopenpyxlによる描画とは分離する。

**確定した条件評価**：各Itemのフィールド条件をシート別に指定した**ANDまたはOR**でまとめ、得られた結果をRecordのItem全件に対して**ANY**で判定する。AND／ORの複雑な入れ子は初期対応の対象外とする。**比較演算子は`==`, `!=`, `<`, `<=`, `>`, `>=`に対応する（質問20）。フィールド値が`None`の比較は演算子を問わず不一致とする（質問21）。**

**質問16の決定**：同一Recordが複数シートの条件に一致した場合は、**一致した全シートへ出力する**。出力シート数による優先順位や重複エラーは設けない。

**質問17の決定**：1 RecordのItemのうち、**いずれか1件が当該シートの条件を満たせばRecordを出力する（ANY）**。条件の判定対象はItemごと、出力対象はRecord全体である。

**質問18の決定**：どのシートの条件にも一致しないRecordは**出力しない**。`items=[]`の場合もItem値条件に一致しないので出力しない。未分類シートへの振り分けやエラー判定は行わない。

**質問19の決定（C）**：同じItem内の複数条件は、**シートごとにAND／ORのいずれかを指定**する。初期実装では条件を一段で結合し、入れ子の論理式は扱わない。

**質問20の決定（B）**：初期対応する比較は、等しい・等しくない・小さい・以下・大きい・以上の6種類（`==`, `!=`, `<`, `<=`, `>`, `>=`）。数量や日付の条件に対応し、範囲は大小比較のANDで表現する。集合への所属や文字列の部分一致は将来の拡張対象とする。

**質問21の決定（A）**：Itemの比較元フィールドが`None`のときは、どの演算子でも**その比較を不一致**とする。例：`数量=None`なら`数量 >= 10`も`数量 != 10`も不一致。複数条件がORなら、ほかの比較条件が成立した場合はItemとして一致してよい。

**条件評価の具体例（説明用）**：各シートで「種別がA」「数量が10以上」を指定した場合。

| Item | 種別 | 数量 | AND（両条件） | OR（いずれか） |
|---|---|---:|---|---|
| Item1 | A | 5 | 不一致 | 一致 |
| Item2 | B | 15 | 不一致 | 一致 |
| Item3 | A | 12 | 一致 | 一致 |

- **ANDの場合**：同じItemが2条件を満たしたときだけ、そのItemは一致する。Item1の「種別A」とItem2の「数量15」を組み合わせてAND一致とはしない。
- **ORの場合**：同じItemがいずれかの条件を満たせば、そのItemは一致する。
- **Recordとしての採否**：上記いずれでも、当該シートの指定ロジックで一致するItemが**1件以上**あればRecordを出力する（ANY）。Recordに含まれるすべてのItem値を、元の並び順で横展開する。

**比較条件の対応例（質問20）**

| 比較の種類 | 指定例 | 初期対応 |
|---|---|---|
| 一致・不一致 | `種別 == "A"`、`種別 != "B"` | 対応 |
| 大小比較 | `数量 >= 10`、`検査日 < 指定日` | 対応 |
| 範囲 | `数量 >= 10` AND `数量 <= 20` | 2条件のANDで対応 |
| 集合への所属 | `種別 in {"A", "B"}` | 対象外（後から追加可能） |
| 文字列の部分一致 | `名称に「検査」を含む` | 対象外（後から追加可能） |

**前提**：条件値は対象フィールドの型（数値・日付等）に適した値とする。対象フィールド値が`None`の場合は`==`・`!=`・大小比較のすべてを**不一致**とする。一方、`None`以外で比較不能な型（例：数値と日付）の組み合わせは、黙って不一致にせず設定・データの不整合としてエラーにする。`None`そのものを判定する演算子（IS NULL等）は初期対象外。比較演算子を増やすために帳票の振り分け機構全体を変更しないよう、条件表現・評価処理を描画から独立させる。

## 2.8 Itemのソート・見出し・空枠（質問22〜24）

| 事項 | 確定したルール | 実装での扱い |
|---|---|---|
| Itemの並べ替え（22＝B／25＝A） | 指定Itemフィールドをキーに、**全シート共通の規則**でRecord内のItemを並べ替える | 初版の昇順・降順、`None`と同値の扱いは第10章の暫定方針に従う |
| 上段見出し（23＝B／26＝B） | **1番目、2番目、3番目…の位置ごとに個別の見出し名**を帳票定義へ指定する。自動連番で代用しない | 必要位置の見出し名が不足した場合は、データを欠落させず明示的にエラーにする（実装案） |
| 0件時の表示（24＝B） | Record・Itemが0件のシートでも**1 Item分の空枠を残す** | 列見出し・罫線などは保ち、データ値・未処理マーカーは空にする |

**並べ替えとシート振り分けは独立する。** 振り分け条件（複数ItemのANY）で各シートに対象Recordを決めた後、横展開用に各RecordのItemを**全シート共通のソート条件**で並べ替える。並べ替えによって条件の真偽や出力先が変わってはならない。位置別見出しの「1番目」は、各Recordの**並べ替え後の1番目のItem**を表す。

**位置別見出しの意味:** 例えば位置1＝「初期」、位置2＝「中間」、位置3＝「最終」と指定しても、全Recordの1番目のItemが必ず業務上「初期」であることは、並べ替えだけでは保証されない。列見出しは各Record共通の**出力位置に対する名前**であり、業務上の意味との整合性は実データの並べ替えキーとともに設計・テストで検証する。

**空枠の意味:** 0件でもItemの列を消去せず、1 Item分の見本幅と列見出しを残す。データ行は、対象Recordが0件なら作成しない。Excelテンプレートで残すのは書式・見出しなどの外観であり、入力用のマーカー値は消す。

## 3. 全体アーキテクチャ

### 3.1 データと帳票定義の合流

```text
Record / Item（業務データ : BaseModel）
                  │
                  │    帳票定義の入力方法を選択
                  │    ┌────────────────────────┐
                  │    ▼                        ▼
                  │  Python側の定義        Excelテンプレートの定義
                  │    │                        │
                  │    └──────────┬─────────────┘
                  │               ▼
                  │     SheetOutputMapping（シート別の抽出条件・上部情報・Record一覧列・Itemフィールド）
                  │     ※ 内部で扱う共通の定義 : BaseModel
                  │               │
                  └───────┬───────┘
                          ▼
                ReportBuilder / DataProjector（共通）
                 ・各Itemの単一／複数フィールド値の条件を評価し
                   いずれか1件が一致したRecordをシートごとに抽出する（ANY）
                 ・抽出後のRecordから上部のキー／値を組み立てる
                 ・抽出後のRecordで上部値の一致を検証。不一致ならエラー
                 ・抽出後に0件なら上部値は空欄、一覧行は0件
                 ・各シートで指定したRecord一覧フィールドを指定順に取り出す
                 ・Item位置ごとに定義された見出し名を割り当てる
                 ・出力対象に選ばれたRecordはItemが0件でも1行に集約する
                 ・Record内のItemを全シート共通の指定フィールドで並べ替えて横方向へ展開する
                          │
                          ▼
                WorkbookData（上部情報＋列見出しの論理情報＋Record行 : BaseModel）
                          │
              ┌───────────┴───────────┐
              ▼                       ▼
       コード定義方式              テンプレート方式
       新規Workbook                既存Workbookを読み込む
       A/B列に上部のキー・値      テンプレート指定位置へ配置
       直下に見出しとRecord行    見本ブロックを複製
              │                       │
              └───────────┬───────────┘
                          ▼
                   openpyxlによる.xlsx出力
```

### 3.2 責務の分担

| 役割 | 担当すること | 担当しないこと |
|---|---|---|
| `Record` / `Item` | 業務データの型と検証 | シート配置や書式 |
| 定義読取（Python／Excel） | シート、**Itemフィールド値に対する各シートのRecord抽出条件**、上部に表示するRecordフィールド名と表示キー、一覧フィールドと列順、Itemフィールド、レイアウト指定の取得 | 業務データの値の加工 |
| `SheetOutputMapping`等 | **シートごとにItemの単一・複数フィールド値を参照する抽出条件とANY評価規則**・上部情報・一覧列と列順・Itemフィールド割当を正規化し、参照先フィールドを検証 | セルの操作 |
| `ReportBuilder` / `DataProjector` | **Itemごとの条件評価とANY方式によるシート別Record抽出**、抽出済みRecordに対する上部キー・値の形成と一致検証、シート別フィールド抽出、Record行の形成、Itemの指定フィールドでの並べ替え（Record内のみ）。抽出結果が0件なら1 Item分の空枠を含む空帳票用データを返す。Itemが0件のRecordも**出力対象に選ばれた場合**は1行生成 | `.xlsx`の読込・書式コピー |
| `WorkbookData` | Excel座標に依存しない上部のキー・値、Itemのグループ順序・指定された見出し名・フィールド名、Record行、空枠の有無 | 見出しのセル結合・罫線 |
| コード側の出力処理 | A/B列への上部情報配置、2段見出しの生成・結合、その直下へのRecord行配置 | 業務上のフィールド振り分け |
| テンプレート側の出力処理 | テンプレート読込、指定位置への上部情報出力、繰り返しブロックの複製、値の入力 | 業務上のフィールド振り分け |
| 保存処理 | ファイル・ストリームへの保存 | 業務データの解釈 |

Itemの**並べ替え設定は帳票全体で1件のみ**持ち、`SheetOutputMapping`の中でシートごとに別設定しない。位置別のItem見出し名は、表示の都合に合わせてシート別に定義してよいが、ソート後の位置番号の意味は全シートで共通とする。

`SheetOutputMapping`は**概念名**であり、クラス名は確定していない。独立した巨大なフレームワークは作らず、初期は小さなBaseModelと関数でよい。

### 3.3 Serializer / Repository との関係

- 出力データへ変換する部分はSerializer的な責務に近い。ただし「データの抽出」と「Excelへの描画」を分ける。
- `Repository`はデータ永続化の必要が生じたときに検討する。Excel帳票を書き出すだけなら単純な保存処理でよい。
- BaseModelは値・設定を表すモデルに用い、実行処理を持つBuilder・Rendererに無理に採用しない。

## 4. Excelテンプレート方式

### 4.1 テンプレートで管理すること

- シートの固定文字・タイトル・書式・罫線・セル結合・列幅・行高・印刷設定
- **Record由来の上部キー・値**（一覧の外に置く情報）を出す位置、および参照するRecordフィールドの指定
- **各シートで個別指定したRecord一覧フィールド**の入力位置・列順・列見出し（段数・結合もExcel上で定義）
- **Item 1件分の見本ブロック**（見出しを含む複数セル・必要なら結合セルを含む）。見出しは1段・2段などを固定せず、見本の形状に従う
- **シートごとに、Itemのどのフィールドをブロック内へ出すか**
- **Itemの並べ替えに使用するフィールドの指定はブック全体で1件だけ**とする。シート別に異なる指定を持たせず、Excel描画前の共通処理で実行する。
- **Itemの出力位置ごとに個別見出し名を指定する**。見本ブロックの書式・見出しの配置はExcel側を利用し、繰り返しブロックの見出し文字列は位置別名称で更新できる設計とする（マーカーの記法は実装時に定める）。
- Recordの繰り返しに使用する見本行（1 Record＝1行）
- 入力Recordが0件の場合も、見出しと帳票の外観を出力できること。Record由来の上部値は空欄にする
- 見本行より下には固定の合計欄・注記・署名欄などを配置しない

例えば、シート1の見本には`{{item.A}}`、`{{item.B}}`、`{{item.C}}`、シート2には`{{item.D}}`のような目印を置く案がある。位置を示すExcelの名前付き範囲との併用を候補とする。

**このマーカー記法は独自仕様であり、openpyxl標準機能ではない。** 実際の表記・範囲指定は実テンプレートを確認して確定する。

### 4.2 Itemの自動拡張（確定要件）

- 1 Item分の見本ブロックを、出力するItem数分だけ右へ複製する。**見出し領域も見本ブロックの一部として複製**し、元テンプレートの見出し段数・結合・書式を保つ。
- **シートごとに異なるブロック幅**（例：3列／1列）を許す。
- ブロックの位置別見出し名は帳票定義から取り出す。ブロックを単純複製して全て同じ見出し名にしない。必要なItem数に対し名称定義が不足していれば、作成を中止して不足位置を示す（初版の安全側の仕様）。
- 書式・罫線・必要な結合セルを、複製先に反映する。
- 同一シートの最大Item数を基に必要な横幅を決め、Itemが少ないRecordの余剰セルは空欄にする。**Itemが0件のRecordも見本行を利用して出力し、Record列にだけ値を設定する。**
- **すべての出力対象RecordでItemが0件の場合**や**出力対象Record自体が0件の場合**でも、**1 Item分の見本ブロックは残す（質問24）**。データセル・未解決のマーカーは空欄とし、枠・結合・罫線を保持する。
- **出力領域の右側はItem拡張専用の空き領域**とし、別の固定セル・表・数式を配置しない。
- 既存の別項目を右へずらす処理は**初期実装の対象外**。想定外の値や結合範囲が拡張先にあれば、安全のためエラーにする。
- Recordの行方向展開は、見本行の書式・必要なセル結合を各Record行に反映し、**1Record＝1行**で下方向に繰り返す。
- **Record一覧の下側も拡張専用の空き領域**とし、合計欄・備考欄・署名欄などの固定項目は置かない。既存項目を下へ移動させる処理は初期実装の対象外。
- 行・列の見本を同時に複製する際は、同じセルへの二重設定や結合範囲の重複が起きないように、書き込み順序・複製範囲を整理する。

**この方式は「Item領域の右側とRecord一覧の下側を空けるテンプレート作成ルール」とセットで成立する。** 見本領域の外側に固定項目を配置したテンプレートは対応対象外とする。既存の結合範囲や数式・グラフなど、拡張時に安全性を保証できない構造は検証で検知し、黙って上書きしない。

### 4.3 複数シートの扱い

- フィールド割当と、上部情報の出力位置は**シートごと**に定義する。
- 例のようにシート1とシート2が異なるレイアウトなら、それぞれ別の見本シートを用意できる構成が自然である。
- **データの値によってItemを分類したり、分類数だけ同じシートを複製したりする設計は、今回の要件から外す。**
- **各シートでItemの単一／複数フィールド値の指定条件に合致するRecordだけを出力する（質問14・15）。** 条件Aに70件、条件Bに30件など、シートによって件数が異なる。
- 条件は**シートごとの出力定義**に置き、表示用Itemフィールドとは独立して指定する。各Item内の条件は**シート別に指定したAND／OR**で評価し、複数Itemは**1件でも一致すればRecordを選択（ANY）**する。複数シートに一致した場合はすべての該当シートへ出力する。
- **Itemのどのフィールドを出力するか**は従来どおりシート別に定義し、**Recordをどのシートへ出すか**とは区別する。
- **どのシート条件にも一致しないRecordは出力しない（質問18）**。一致しないRecordを集めるシートは作らず、これを理由とするエラーも出さない。
- 抽出結果が0件になったシートも削除せず、上部の値が空欄の空帳票を出す。
- テンプレート自体は上書きせず、別の出力ファイルを生成する。

### 4.4 技術上の制約

openpyxlのセルコピーは、Excelの参照関係まで自動的に安全に管理する万能な複製操作ではない。

- `insert_cols()`などは数式・テーブル・グラフの参照関係を全面的に修正しない。
- 結合セルの値の書込位置や、コピーする罫線の扱いを確認する。
- 画像・グラフ・図形等を含むテンプレートの読み書きは、実ファイルで保持状態を検証する。
- ワークシートの最大行数・列数、シート名の制限、印刷範囲の扱いを検証する。

## 5. コード定義方式

### 5.1 初期レイアウト（質問7・11で確定）

1. 各シートの**A1から下方向へ、上部情報のキー**を順番に並べる。
2. **B1から下方向へ、それぞれのキーに対応する値**を並べる。
3. すべてのキー・値を書いた**次の行を見出し上段**、さらにその次の行を**見出し下段**とする（空行は挟まない）。
4. Itemの**出力位置ごとに指定された個別の見出し名**（例：初期測定、中間測定、最終測定）を上段に表示し、対応列数分だけ**横結合**する。下段はそのシートで選択したItemフィールド名とする。番号から自動生成しない。
5. 左側のRecordフィールド見出しは原則**上下2行を縦結合**する。
6. **見出し下段の次の行**からRecordを1件1行で下へ並べる。値はシート別に指定されたRecordフィールド、その右側にItemの選択フィールドを**指定フィールドで並べ替えた順**に並べる。**Itemが0件のRecordはRecordフィールドだけを出力し、Item列を空欄にする。**
7. Record一覧の下とItem領域の右側は、既存の固定項目を置かない（質問5・6）。
8. **入力Recordが0件でも上部のキー（値は空欄）と2段見出し・1 Item分の空枠を出力**し、Recordデータ行は作成しない。

上部情報が**N件**なら、見出しは**N+1、N+2行目**、Recordデータ開始は**N+3行目**とする。セル番地を固定値でハードコードしない。

**見出しのセル結合はコード定義方式の出力責務**であり、`Record`／`Item`のBaseModelには持たせない。

### 5.2 テンプレート方式との共通点・相違点

- Python側で「どのシートの上部に、**Recordのどのフィールドをキー・値として出すか**」「**シートごとにRecordのどのフィールドを、どの順番で一覧へ出すか**」「Itemのどのフィールドを横展開するか」を指定する。
- フィールド割当と論理データは、テンプレートから読み取るものと**共通の内部モデル**へ変換する。
- 共通の`WorkbookData`から、コード定義方式では**A/B列への上部情報＋2段見出し（必要な横結合・縦結合）＋Record行**を持つ新規Workbookを生成する。
- テンプレート方式はExcelに指定された位置へ出す。**2段見出しを強制せず、テンプレート側の見出し構造を尊重する**。A/B列配置に合わせて作り直す必要もない。
- `WorkbookSpec`・`ReportLayout`・`CellSpec`は必要に応じて採用するが、**テンプレートの全書式をこのモデルに変換しない**。

### 5.3 上部情報の取得元と一致検証（質問8・9で確定）

- A/B列のキー・値は**Recordが持つフィールド**から取得する。別の帳票共通データや設定オブジェクトを入力として必須にはしない。
- **各シートで上部に出力したいRecordフィールド**を帳票定義から選ぶ。選択内容と表示名はコード方式ならPython側、テンプレート方式ならExcel側で指定する。
- **一覧用のRecordフィールドは上部情報とは別に、各シートで選択・並び順を指定する（質問10＝B）。** 上部情報として選んだフィールドを一覧にも出すことは可能。
- 上部情報は一覧の各行とは独立し、**シートごとに1回だけ**出力する。
- **上部に指定したフィールドごとに、そのシートへ抽出されたRecordの値が一致することを検証する。** 別シートのRecordとは比較しない。不一致ならフィールド名と対象Recordが分かるエラーとして出力を中止する。
- 一致判定は**Excel表示形式に変換する前のデータ値**に対して行う。異なる値を表示上の丸め等によって同一扱いしない。
- **入力全体が0件、またはシートごとの抽出結果が0件**の場合も空帳票を作成する（質問13・14）。上部キーは残し、値は空欄とする。一致検証は実施しない。
- キーの並び順や表示名を指定する細かな記法、デフォルト書式、空欄値の書式などは実装時に定める。

## 6. 実装順序（第10章で詳細化）

既存の要件を小さな処理単位に分け、**共通データ処理 → コード方式 → テンプレート方式**の順に実装する。テンプレートの書式複製は難易度が高いため、論理データの正しさを先に確認する。

| 段階 | 作業 | 完了条件 |
|---|---|---|
| 1 | `Record` / `Item`の実フィールドと帳票定義（共通ソート・各シートの抽出条件・出力項目・位置別見出し名）を整理 | Python内での型・設定の検証が通る |
| 2 | SheetごとのItem条件（AND/OR・ANY）によるRecord抽出、共通ソート、上部値の一致検証、`WorkbookData`生成 | Excelを使わずシート別の値・列順・空帳票をテストできる |
| 3 | **コード定義方式のRenderer**を実装 | A/B列の上部情報、2段見出し、結合・横展開・縦展開を.xlsxで確認できる |
| 4 | **テンプレート定義の読取とRenderer**を実装 | 元.xlsxの見本行／列を複製し、同じ`WorkbookData`で値と位置別見出し名を描画できる |
| 5 | エラー、空枠、結合・罫線・幅・印刷、実テンプレート回帰試験 | データの欠落・上書きなく、元テンプレートを変更せず別ファイルに保存できる |

段階ごとの詳細・クラスの責務・暫定方針は**第10章**を参照する。

## 8. 要件確定事項と実装時の検討事項

**質問8で確定した事項（B）:** 上部キー・値は、**Record自身が持つフィールド**を情報源とする。別の帳票共通データを必須にはしない。コード方式・テンプレート方式のどちらでも、出力対象フィールドの指定方法だけが異なる。

**質問9で確定した事項（A。質問14により検証範囲を明確化）:** 上部に表示する各Recordフィールドの値は、**そのシートに振り分けたRecord全件で一致することを必須**とする。不一致なら出力しない。入力全件を通した一致は要求しない。判定は表示変換前のデータ値に対して行う。

**質問10で確定した事項（B）:** **一覧表に出力するRecordフィールドは、シートごとに自由に選択し、列順も指定する。** 上部で使うRecordフィールドを一覧にも指定できる。Python定義方式ではPython側、テンプレート方式ではExcel側で指定し、共通のシート別マッピングに正規化する。

**質問11で確定した事項（C、Python方式はB）:** 見出しの作成方法は方式別に選ぶ。**Python定義方式では2段見出し**とし、Item単位の上段に帳票定義で指定した見出し名を横結合して表示し、下段にフィールド名を表示する。Recordフィールド見出しは原則2行を縦結合する。**テンプレート方式ではExcel上の見出し構造をそのまま利用・繰り返す**。共通化するのはフィールドの対応とItemの順序であり、見出しの見た目まで統一しない。

**質問12で確定した事項（A）:** `items`が0件のRecordが**出力対象になった場合**、Record自身のフィールドを1行出力し、Itemのセルを空欄にする。**今回のItem値条件（ANY）ではItemが0件なら一致せず、出力対象にならない（質問18）**。

**質問13で確定した事項（A）:** Recordが**0件**でも各シートを作成し、列見出しを表示する。上部のキーは残すがRecord由来の値は空欄にする。データ行は作成せず、上部値の一致検証も行わない。

**質問14で確定した事項:** **シートごとに条件に合うRecordだけを振り分けて出力する。** 例えばシートA 70件、シートB 30件。抽出とフィールド割当は別の責務とし、抽出後に上部値検証・Item横展開を行う。

**質問15で確定した事項（B、補足あり）:** シート別の振り分け条件は、**Itemの単一または複数のフィールド値を参照する指定条件**とする。特定の判定フィールド・判定値に限定しない。条件は帳票定義で指定し、コード方式とテンプレート方式から共通の条件表現に変換する。

**質問16で確定した事項（A）:** **同じRecordが複数シートの条件を満たす場合、該当するすべてのシートにそのRecordを出力する。** 同じシート内では1 Record＝1行を保ち、シート間の重複を許す。優先順位による排他振り分けや重複エラーは導入しない。

**質問17で確定した事項（A）:** **同じRecord内のItemが1件でも各シートの指定条件を満たせば、そのシートへRecord全体を1行出力する（ANY）。** 一致していないItemも含め`items`の全件を、質問22・25の**共通並べ替え規則を適用した順序**で横展開する。条件はシート別に独立して評価する。

**質問18で確定した事項（A）:** **どのシート条件にも一致しないRecordは出力しない。** 未分類シートは作らず、エラーにもならない。Itemの値を調べるANY方式では、`items=[]`も条件に一致しないRecordとして扱う。

**質問19で確定した事項（C）:** **同一Item内の複数条件はシートごとにAND／ORを選べる**。ANDでは同じItemがすべての条件を満たす必要があり、ORではいずれかを満たせばよい。初期実装では入れ子の条件式は扱わない。Record内の複数Itemは従来どおりANYで評価する。

**質問20で確定した事項（B）:** 比較演算子は**一致・不一致・大小比較の6種類**（`==`, `!=`, `<`, `<=`, `>`, `>=`）を初期対応とする。範囲は大小比較のANDで表し、INや部分一致は後から拡張する。

**質問21で確定した事項（A）:** 比較対象のItemフィールドが`None`なら、**比較演算子にかかわらず不一致**にする。`!=`でも不一致であり、AND/ORはこの結果を用いる。`None`以外の型不一致はエラーとして区別する。

**質問22・25で確定した事項（B・A）:** `Record.items`は**全シート共通の指定Itemフィールド**で並べ替えてから出力する。各RecordのItemだけを並べ替え、Record一覧の順序は変えない。入力モデルのリストを破壊的に書き換えない。昇順／降順、同値・`None`の扱いは第10章に暫定方針を記載した。

**質問23・26で確定した事項（B・B）:** Itemの上段見出し名は**出力位置ごとに個別指定**する。Python定義方式はPython側の帳票定義、テンプレート方式はExcel側の定義を使用する。見本の書式・配置は維持し、位置別名称を挿入する。見出し名を単純な連番から自動生成しない。

**質問24で確定した事項（B）:** 出力対象のRecordやItemが0件でも、**1 Item分の空の見本ブロック**を帳票に残す（コード・テンプレート両方式）。数値・文字列の仮値や未解決マーカーは表示しない。

**質問25で確定した事項（A）:** Item並べ替え条件は**ブック全体で1つ**とし、シート間で同じRecordのItem順序を統一する。

**質問26で確定した事項（B）:** Item見出しを**出力位置ごとに個別指定**する。指定名の不足を黙って別名・連番で補わず、エラーで通知する初版仕様を採用する（実装上の補足）。

**基本要件の確認は質問26で一区切りとする。** 今後は第10章の実装設計・実物のテンプレート検証を進める。

**後で決める事項（必要が生じた時点で判断）:**

- **実装上の暫定値:** ソート方向（初版は昇順を既定とする案）、同値では元順維持、ソートキーが`None`なら末尾に配置する案。これはユーザーが回答した確定仕様ではなく、実データを見て調整する。
- **明示する制約:** 指定済みの位置別見出し名よりもItemの最大件数が多い場合は、帳票を不完全なまま生成せずエラーとする（追加の位置名を設定して対応）。
- テンプレートの目印や名前付き範囲の具体的な表記。
- 複雑な結合・数式・画像を含むテンプレートへの対応範囲。
- どのシートにも合わないRecordの扱いは**質問18で確定済み（出力しない）**。Itemが0件の場合も同様。
- 複数Itemに対する評価方法は**ANYで確定済み**。同一Item内のAND／OR指定は**質問19で確定済み**。比較演算子の範囲は**質問20で確定済み**。演算子の記法・値型の表記は実帳票に合わせる。
- 欠損値（`None`）の比較条件は**質問21で確定済み（不一致）**。`None`以外で比較不能な型はエラーとする。具体的なエラーメッセージ・入力の厳密な型検証は実装時に決める。
- Item領域の右側とRecord一覧の下側には固定領域を置かないことが確定済み。**固定項目を移動させる自動レイアウト調整は対象外**とする。

## 9. 特に避けること

1. **Itemのクラス型とシート分類を混同する。** 今回はItemのフィールド単位で出力先を選ぶ。
2. **Itemインスタンスを切り分けてシートへ配布する。** 今回行うのは、まずRecord単位の振り分け、その後に各シートでItemの指定フィールドを取り出す処理である。
3. **Itemの出力フィールドとセル位置を業務モデルへ埋め込む。** 変更が帳票に閉じなくなる。
4. **テンプレートを読み込んで、その全書式を共通のPythonモデルへ複写する。** 二重管理になる。
5. **可変拡張先のセルを無検証で上書きする。** 正常なデータ欠落・帳票破損に気づけなくなる。
6. **Item領域の右側に固定項目を配置したテンプレートを許容する。** 今回は右側を空ける運用とし、自動移動の機能を増やさない。
7. **Record一覧の下側に固定項目を配置したテンプレートを許容する。** 今回は下側を空ける運用とし、合計欄などを自動で移動させる機能は作らない。

|---|---|---|
| `ReportSpec` | ブック全体の並べ替え規則と複数のシート定義 | `BaseModel`。**ソート条件はここに1件だけ**置く |
| `SheetSpec` | シート名、Item抽出条件、上部情報フィールド、Record一覧列、Item出力フィールド、**位置別見出し名** | `BaseModel`。シートごとに別の出力列を定義可能 |
| `ConditionSpec` / `ComparisonSpec` | Item内のAND／ORと6種の比較演算子、右辺値 | `BaseModel`。条件の表現をExcel描画と分離 |
| `DefinitionLoader` | Python定義またはExcelテンプレート定義を共通の設定形式へ変換 | 2方式で入力方法を分けるが、出力する`ReportSpec`の意味は揃える |
| `RecordSelector` | 各SheetSpecについてItemをANY評価し、Recordをシート別に抽出 | 通常の関数／クラス。Itemが0件の場合は現行ANY条件では不一致 |
| `ItemSorter` | **全シート共通のソート条件**で各RecordのItemの出力順を作る | 入力の`Record.items`を変更しない。見出しの位置と順番を揃える |
| `ReportProjector` | 抽出済みRecordの共通値チェック、セルに出す値・列順・見出し位置を構成 | 通常の関数／クラス。Excelセル番地・書式は持たない |
| `WorkbookData` / `SheetData` | シートごとの上部項目、Record行、Itemブロックの値と見出し名 | `BaseModel`。**値の構造**のみ保持する |
| `CodeRenderer` | 新規WorkbookにA/B列、2段見出し、結合、下方展開を実現 | `openpyxl`の操作をここに閉じ込める |
| `TemplateRenderer` | テンプレート読込、見本行・列の書式／結合のコピー、位置別見出し、値の配置 | `openpyxl`の操作をここに閉じ込める。テンプレートの全書式をBaseModel化しない |
| `Exporter`（必要なら） | Workbookをファイル／ストリームに保存 | 当初は小さな保存関数でよい。Repositoryの導入は必須にしない |

**クラス名は確定ではなく責務の候補である。** 小さく実装し、不要なクラスは統合してよい。`BaseModel`を使うのは値・設定の構造が中心であり、動作する処理クラスには無理に継承させない。

### 10.2 1回の出力処理の手順

1. `Record`一覧、帳票定義（PythonまたはExcel）、テンプレートの有無を受け取る。
2. 定義を共通`ReportSpec`へ正規化して検証する。**ソート条件は共通であること**、**位置別見出しは必要数揃っていること**、参照するRecord / Itemフィールドが存在することを確認する。
3. 各シートのItem条件を独立して評価し、1件でも一致するItemがあればRecordをそのシートへ採用する。該当なしのRecordは出さず、対象0件のシートは残す。
4. 採用Recordについて、シート内で上部の共通値を検証する。不一致ならExcel出力を始める前にエラーで中止する。
5. **共通ソート設定によりItemの表示順を生成する。** 同じRecordが複数シートにあってもItemの位置は一致させる。元のデータは変更しない。
6. 各シートのRecordフィールドとItemフィールドを選択し、必要なItem位置に個別見出し名を割り当てて`WorkbookData`を作る。0件なら1 Item分の見本枠を確保する。
7. `CodeRenderer`または`TemplateRenderer`でExcelへ配置する。テンプレートの可変領域に想定外の既存データがあれば上書きせずエラーにする。
8. すべての検証・描画に成功した場合だけ、元テンプレートとは別の出力先に保存する。

### 10.3 着手順（最小の動作から増やす）

| ステップ | まず作るもの | 動作確認の完了条件 |
|---|---|---|
| 1 | 実際のRecord / Itemと最小`ReportSpec`、シート条件 | Excelを使わず、複数シートへのRecord抽出、AND/OR、None判定、0件の挙動がテスト可能 |
| 2 | 全シート共通ソート、位置別見出し名、`WorkbookData` | 2種類以上のItemの並べ替えで全シート同順。名前不足時は明示エラー。入力モデルは不変 |
| 3 | **先にコード方式のRenderer** | A/B列の上部情報、2段見出し、Itemの横展開、Recordの縦展開、空枠を.xlsxで確認 |
| 4 | **続いてテンプレート方式のRenderer** | 見本ブロックを複製して書式・結合を維持。定義読み込みで同じ`WorkbookData`を再利用 |
| 5 | 結合・罫線・幅・印刷・例外対応の強化 | 実際の.xlsxを開いて確認し、コード方式とテンプレート方式の論理データが一致する |

最初の到達点は、**同じRecord一覧と同じ論理定義から、コード方式・テンプレート方式で同じ値を別レイアウトへ出せること**とする。全機能を一度に開発しない。

### 10.4 実装時の初期方針（ユーザー回答とは区別）

| 論点 | 実装に着手するための暫定案 | 理由 |
|---|---|---|
| ソート方向 | **昇順**を既定。降順の指定を追加しやすい設定にする | 当面の挙動を決めつつ、要件変更を局所化する |
| ソートキーが同値 | **入力`items`内の相対順を維持** | 出力結果を予測可能にする |
| ソートキーが`None` | **末尾に配置**。昇順／降順でも未設定値を先頭にしない | 欠損値が最初の位置別名称を占めることを避ける |
| 位置別見出し名の不足 | **エラーとして保存しない**。不足したItem位置とシート名を示す | 列名の取り違えや、意図しないデータ欠落を防ぐ |
| Itemが0件のシート | 1 Item分の**見出しと外枠だけを維持**。値・未解決マーカーなし | 質問24＝Bに従う |
| テンプレート定義の具体的記法 | 実物の.xlsxを確認してから決定する | 記法の先行固定による修正を避ける |

**これらは、質問25・26の回答で直接確定した事項ではない。** 実装時に実際のフィールド型・既存帳票の規則と照らし合わせ、合わない場合はここだけ調整する。

### 10.5 実物を用いて最初に確認する資料

- `Record`・`Item`のフィールド一覧と型（`None`許容、比較・ソートに使うフィールドを含む）。
- **シートA / Bの抽出条件**（各ItemのAND/OR・比較演算子・比較値）と、各シートへ出すフィールド名。
- **並べ替えに使用する共通Itemフィールド**および位置別に付けたい名称の例（最大Item件数も併記）。
- テンプレート.xlsxの見本（見出し領域、Item見本列、Record見本行、結合・書式）。

この4点があれば、以降はユーザーへ抽象的な選択質問を増やさず、**実コード・実テンプレートを見ながら実装設計を進める**ことができる。
